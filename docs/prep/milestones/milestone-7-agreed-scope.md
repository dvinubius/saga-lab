# Milestone 7 — Agreed scope

Build specification: [GitHub issue #66 — Public release: shared VPS deployment, read-only investigation and bounded use](https://github.com/dvinubius/saga-lab/issues/66).

These decisions refine milestone 7. Everything in the milestone 7 entry in [Milestones](../saga-lab-04-milestones.md) is in scope. The [Technical Plan](../saga-lab-02-technical-plan.md) §9 and the [Observability](../saga-lab-03-observability.md) document §8–9 are amended in place to match. Expected traffic is organic only, about one visitor a week for a few minutes; there is no synthetic traffic.

- **Hosting:** the existing Hetzner VPS (2 vCPU, 3.8 GiB RAM, no swap, 40 GB disk), beside Hooklook, zibs and the platform monitoring, in `/opt/saga-lab`. Saga Lab fits as long as at least 15 GB of disk stays free (Hooklook's 12 GB deploy allowance plus 3 GB platform headroom) and at least a quarter of RAM stays available. Measured before release: about 26 GB free after pruning the host's build cache, and roughly 0.8 GB of new images and 0.5 GiB of memory for Saga Lab. Grafana is pinned to `13.0.6`, the image zibs already runs, so its layers are not stored twice. Every container gets a `mem_limit`, and Docker logs rotate at 3 × 10 MB. The OpenTelemetry Collector stays.
- **Ingress:** owned by [hetzner-one](https://github.com/dvinubius/hetzner-one), the VPS's shared Caddy, not by this repository. Hetzner-one gains a `saga.dinubarbu.com` site and creates a `saga-lab-edge` network that Saga Lab joins externally. Caddy proxies the site to the Transfer Service under the alias `saga-lab` and `/grafana/*` to Grafana under the alias `saga-lab-grafana`. No Saga Lab service publishes a public port. Caddy's `caddy-ratelimit` limits each direct client address (`{remote_host}`) to 20 POSTs a minute on the app (`/transfers`, `/top-ups`, `/reset`, `/api/*`) and 300 requests a minute on `/grafana/*`. There is no rate limiter in the application. The visitor cookie gains `Secure` through configuration.
- **Grafana and the trace link:** anonymous visitors are Viewers. The login form, snapshots and public dashboards are disabled; the admin password comes from the VPS's environment. Grafana is served from the `/grafana` sub-path and proxied whole, because an externally shared dashboard cannot take a URL variable; this departs from hetzner-one's narrow allowlist for the other sites' public dashboards. A provisioned Trace dashboard holds one Traces panel that queries `${traceId}`. "Trace →" opens that dashboard with the trace ID and the transfer's time window from milestone 6, replacing the Explore link, which Viewers cannot open. The local stack uses the same Viewer configuration.
- **Visitor identity:** the cookie carries a random secret token of 64 hex characters, and the visitor ID is its SHA-256 hash. Services, messages, spans and logs see only the ID, so a trace never reveals a cookie. A cookie that is not 64 hex characters is replaced by a new visitor.
- **Admission limit:** at most five transfers await admission, not counting the one holding the demonstration slot, checked in the transaction that queues a transfer so the limit is exact. A Bank B unavailability submission beyond it creates no transfer: the JSON API answers `503 Service Unavailable` with `Retry-After`, and the page shows the form again with "The Bank B unavailable demo is busy right now. Try again in a minute, or pick another scenario." The form does not disable the scenario in advance.
- **Retention:** visitor expiry after seven days unseen. Each request updates the visitor's last-seen time; an hourly Transfer Service sweep deletes expired visitors through the visitor reset path, skipping a visitor whose transfer is pending or holds the demonstration slot. Each bank prunes its own inbox entries older than seven days. Tempo keeps traces for 168 hours, so a remaining transfer's trace link keeps working. Crawlers without cookies each create a throwaway visitor, bounded by the rate limit and expiry; there is no cookie check. There are no backups: the data is fictional and short-lived.
- **Deployment:** follows Hooklook's [deployment runbook](https://github.com/dvinubius/hooklook/blob/main/docs/deployment-runbook.md), trimmed. `test.yml` runs the full `make test` on pull requests into `main` and before every deployment. `deploy.yml` plans the mode over read-only SSH from the last verified commit in the VPS manifest: `none` for docs, tests and agent notes only, otherwise `full`. A full deployment publishes one services image to GHCR, uploads a `git archive` bundle, and runs `remote-deploy.sh` on the VPS, which takes a host lock, checks Docker, the `saga-lab-edge` network and the 15 GB disk headroom, snapshots the live files, pulls the image by digest, recreates the stack without building, and verifies it. Verification: loopback and public `/readyz`, Grafana serving the Trace dashboard, and `scripts/smoke.sh https://saga.dinubarbu.com`. Any failed check restores the snapshot. A manual `rollback <snapshot>` exists, `scripts/compose.sh` pins the running image, the manifest records the verified commit, and five snapshots are kept. A dedicated `saga-lab-deploy` account owns `/opt/saga-lab`; PostgreSQL, RabbitMQ and Grafana admin secrets live only in `.env` on the VPS. The repository becomes public before the first deployment, with a `production` environment and branch protection requiring `test`.
- **Smoke run:** `scripts/smoke.sh <base-url>` runs all five scenarios as one new visitor through the JSON API and checks each outcome summary's balances and counts. The Bank B unavailability step waits up to two minutes for admission and is skipped with a warning when refused by the admission limit, so a busy demonstration never rolls back a sound deployment. Every other failure fails the deployment.
- **Documentation:** follows Hooklook's layout. The README becomes the portfolio entry point: the logo, a tagline, links to the docs, a live status badge and the site link, what the demonstration shows, and quick local run and test instructions. `docs/README.md` is a routing index, pointing agents to `docs/prep` for intended behavior. Topic documents: `architecture.md` (services, broker, databases, inbox and outbox, a diagram), `scenarios.md` (the five scenarios' semantics, the invariants, and representative demonstrations with their expected history and outcome), `observability.md`, `http-api.md`, `development.md` (today's README detail on running, resetting and testing), `deployment-runbook.md`, `security.md` (visitor token, Grafana exposure, telemetry rules) and the existing `limitations.md`.
- **Polish:** the stale README status and Known gaps, docs still naming `CreditAccepted` (the code says `CreditConfirmed`), a short introduction on the home page saying what the demonstration is, and a footer link to the GitHub repository.
- **Operator actions, not automated:** pruning the VPS build cache (done before release), DNS for `saga.dinubarbu.com`, the hetzner-one change and its deployment, the deploy account and SSH key, the VPS `.env`, making the repository public, and the GitHub environment and branch protection.
- **Primary test boundary:** over HTTP against the running stack: the admission limit refuses a sixth waiting transfer without creating it and admits again once a place frees; an invalid cookie gets a new visitor; an expired visitor is deleted and a pending one is not. The smoke script runs against the local stack in the test suite. The Grafana Trace dashboard, the home page introduction and the deployed site get an eyeball checklist, not browser tests.
